## 紙張與掛點

紙板主體厚度為信封可見寬度的 **2.2%**；小倒角後約 2.32%，含最高蠟封約 2.8%。外緣沿原 PNG 的 alpha 最大連通輪廓建立，金色蝴蝶結的兩個孔洞保留，不使用矩形 Box 或 Sprite。取樣 4px、簡化約 4px，忽略原匯出圖中孤立的近透明雜點；原檔及手繪像素不變，產生資料記錄來源 SHA-256。

正面／微凸封口／蠟封共用原 PNG 的對應 UV。背面同輪廓，從同張原圖的空白紙紋區取樣並加奶油色調與淡摺線，不另生成插畫或複製貼圖。材質 roughness 1、metalness 0，不加反射亮面。微凸層下有低透明局部陰影，沿用場景現有柔光，沒有啟用昂貴的全場景陰影貼圖。

一般信寬為樹實際高度的 8.5%，自己的金色信為 9.2%。樹原有包圍盒正規化保持不變；初次掃描頂點時，以 24 個高度帶 × 24 個方位記錄真實外緣頂點，掛線頂點位於對應樹枝表面。五層掛點位於約 76%、64%、52%、40%、28% 樹高，左右方位 ±0.65 rad。短弧形細線連接頂部 pivot 與紙身，固定微小傾角由願望 ID 決定。

信封隨樹的實際旋轉展示側面與背面，不朝鏡頭 billboard。樹和信封以深度緩衝自然互相遮擋；原生閱讀按鈕另外使用低面數、僅在 CPU 計算的樹冠代理檢查遮擋，避免逐幀射線掃描原樹約 75 萬個三角形。代理不是逐片樹葉的精確遮擋模型，因此極端斜角的按鈕判定可能略保守；畫面本身仍使用真實模型深度。

## 動態與效能

既有信封沒有 idle 動畫，公開列表刷新保留相同 ID 的實例、掛點和姿態。只有原寄信流程確認成功傳入的新金色信封，會做 3.2 秒小幅衰減晃動，結束精確設回靜止角度；紙身、封口、蠟封及掛線共用頂部 pivot，頂端位置固定。重新整理載入舊信或一般資料更新不觸發。

支援 `prefers-reduced-motion`，動態偏好改變時立即停止。沿用原 Renderer、像素比上限及頁面隱藏暫停機制；精靈暫停時，只有尚未結束的寄信晃動會繼續要求畫格。兩張原貼圖及各款幾何／材質在所有實例間共用，銷毀時只釋放一次。放大預覽兩種信封合計 2,250 三角形／24 draw calls，未包含原本的樹或精靈。
