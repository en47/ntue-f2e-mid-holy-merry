# Santa 流程順暢化計畫（2026-11-13）

這份文件是給下一個工作階段（Claude Code）直接照著做的計畫，也是這批修改的設計依據。做完每一階段，把實際情況補回這份文件的「狀態」欄。

## 背景與規則（先讀）

- 專案規則在 `CLAUDE.md`，Santa 解謎的設計在 `docs/SANTA-PUZZLE-DESIGN.md`，進度在使用者的記憶檔。以下只列這批工作最常用到的：
  - 一律繁體中文：回覆、文案、文件、測試名稱。使用者用語音輸入可能出現簡體字，網頁上不可出現簡體字。
  - 美術一律紙雕 SVG（`paperLayer`／`paperFilter`／`cabin-paper`），會動的部位拆成獨立圖層用 CSS 或場景移動，不要動畫 SVG 內部。不要 CSS 平塗、漸層、虛線的物件。
  - 每批修改各開分支（從 `final`），`npm test` 結束碼 0 才 commit，`--no-ff` 併回 `final`。**不推送任何分支。** `main` 凍結到 12/18。
  - commit 訊息不要加 `Co-Authored-By: Claude`。
  - 改 JS／CSS 後執行 `node scripts/stamp-modules.mjs`；改紙板畫法後執行 `node scripts/build-cabin-boards.mjs`；新增中文字後若 `npm test` 列出缺字，執行 `scripts/build-hand-font.py`（見 `docs/HAND-FONT.md`）。
  - 不改 Home／Intro／Game／Wish 頁；不改 GLB；不改鏡頭與場景配置；不改謎題答案與願望點數規則；不重寫五位替身的見面禮支線。
  - `bug/` 不進版本控制（已在 `.git/info/exclude`）。
- Node 在 `export PATH="$HOME/.nvm/versions/node/v26.13.0/bin:$PATH"`；本機網站 `python3 -m http.server 5511 --bind 127.0.0.1`。

## 分級驗收（使用者 2026-11-13 的要求）

使用者覺得每個小修改都跑完整瀏覽器驗收太久（一輪 45 分鐘）。改成：

| 修改種類 | 驗收 |
| --- | --- |
| 文案、美術、位置 | `npm test`（約 1 分鐘）＋ 截圖給使用者看 |
| 一個段落的互動 | 上面的，再加對應的那一支 `scripts/check-santa-*.mjs`（桌機＋手機約 10 分鐘） |
| 合併進 `final` 前 | 完整回歸一次：七支腳本桌機＋手機（含 `check-santa-playthrough.mjs`） |

- 瀏覽器驗收**一支一支依序跑**，不要兩個瀏覽器並行（並行時頁面會載入逾時而誤判）。
- 每一階段做完先讓使用者試玩，確認流程順了再跑合併前的完整回歸。
- 回報時說明跑了哪些、沒跑哪些。

## 設計原則：東西說話，不是系統說話

使用者明確表示提示太多會「AI 味太重」。所以：

1. 不要跳文字提示。卡住時用場景裡的小動作暗示（旗子晃、鈴鐺響、紙角翹起、微微發光）。
2. 每個鎖都看得到缺什麼，每個道具都暗示用在哪（形狀對應）。
3. 能用圖就不用字。卡片、線索本、小房間的東西都要減字。
4. 提示只在玩家主動要時給：打開線索本按「給我提示」、點聖誕老人問他。
5. 聖誕老人只在故事轉折開口，句子短，用他的口吻。

## 階段一：開場與鎖鑰對應（小）

1. **開場指向郵筒**：鏡頭停在小屋前時，郵筒的旗子「叮」一聲豎起來並輕晃幾下（場景動畫，`cabin-scene.js`）。開場提示（`js/santa.js` 的 `showTip`）改成指向郵筒，例如「郵筒的旗子豎起來了」。目的：前 30 秒教會三個動作：看（信）、撿（地衣包）、用（餵食槽）。
2. **郵筒可以關**：打開後再點郵筒就關上（`cabin-play.js` 的 `games.mailbox`，`repaint('mailbox', { open: false })`），要看信時再打開。關上時信和包裹的按鈕收起來。
3. **聖誕老人的去向**：
   - 搖椅紙條（`CHAIR`）加背面：檢查卡可翻面（`inspect` 已支援 `back`），背面手寫「麋鹿那邊要忙一陣子。—— S.」。
   - 小房間的交接表上貼一張聖誕老人的便條（在交接表卡片最上面，`cabin-secret.js` 的 `shiftLog`）：「弄濕了……誰來幫我補好？補好我就回來。—— S.」補好後便條換成「謝謝！—— S.」或消失。這讓最難的謎題變成「幫聖誕老人一個忙」，也回答了他何時回來。
4. **形狀對應**（`cabin-items.js` 的 `ITEM_ART` 與相關紙板）：鑰匙柄刻一片冬青（抽屜鎖孔旁本來就有冬青）；火柴盒上畫爐火；把手末端畫成方榫，絞盤上是方孔。只改圖，不改玩法。

驗收：`npm test`、截圖（郵筒開／關、紙條背面、交接表便條、三樣道具），請使用者試玩第一章。

## 階段二：聊天框改成預設對話（中）

使用者決定：聊天框**不用 AI**，改成預設對話。

- 右側的 `cabin-chat`（`js/components/cabin-chat.js`）預設收成一個小圖示（聖誕老人的頭像紙片），桌機放右上、手機放右下口袋旁；不再佔畫面。
- 點場景裡的聖誕老人（`ROOM_PROPS` 的 `santa`）或點小圖示，打開對話框。對話框是紙雕卡片，上面是聖誕老人的一句話，下面兩到三個可以點的問句（紙籤按鈕），例如「我現在該做什麼？」「這是什麼地方？」「你剛剛去哪了？」。
- 回答依目前進度（`goal(progress)` 與 `progress` 的狀態）從預設表挑：每個目標準備一句聖誕老人口吻的回答，**只說方向，不說答案**（和 `GOALS[id].task` 同義但用他的語氣）。文字放在 `js/data/` 的新資料檔。
- 聖誕老人不在家時，小圖示變成搖椅紙條的圖，打開是紙條內容，問句換成「他去哪了？」（回答：紙條背面那句）。
- 說過的話不要重複推銷：同一個目標第二次問，換第二句（最多兩句），之後只回「慢慢來，不急。」
- 保留原本聊天框的 DOM 與樣式鉤子給之後的 AI 版本，但目前不顯示輸入框。`tests/smoke.mjs` 裡關於聊天框的斷言要同步改。

驗收：`npm test`、截圖桌機與手機、`check-santa-room.mjs` 桌機＋手機、請使用者試玩。

## 階段三：卡住時的場景暗示（中）

- `cabin-play.js` 或新模組：60 秒沒有任何存檔變動（`save()` 掛勾）且沒有卡片開著時，**只有**和目前目標相關的那一樣東西每隔約 20 秒做一個小動作。用動作，不用光（使用者 2026-11-14 覺得院子隨機冒出的光暈很突兀，已拿掉）：雪堆噴一點雪、穀倉的維修標籤晃一下、麋鹿用鼻子推一下餵食槽、書櫃的金色書脊輕輕一跳、交接表的紙角翹起來。對應表：目標 → 場景物件 id（例如 `yard` → 還沒碰過的那個角落；`bookcase` → 書櫃；`log` → 交接表；`join` → 登記簿；`cord` → 舊紀錄簿）。
- 一次只動一樣；只用 transform；減少動態時不動。
- 目標換了時，線索本冒紅點（`notebook.check()` 已能偵測），不跳文字。

驗收：`npm test`、用 Playwright 等 60 秒截圖確認只有一樣在動。

## 階段四：小房間減字（中，先問過使用者）

- 不改交接表的答案、不改推理方式。

驗收：`npm test`、截圖、`check-santa-secret.mjs` 桌機＋手機（它會檢查唯一解與四種順序）。

## 階段五：線索本改版（大）

- 線索變成貼紙：每條線索一張小紙雕圖（畫那樣東西本身）加兩到四個字的名字，點開才放大看全文。新線索「啪」地貼上（CSS transform 動畫）。
- 三個紙籤分頁：目標／線索／見面禮。目標頁一張小插圖加 `task` 那一句，提示收在「給我提示」後面，一次一層。
- 封面五格章節郵票：院子、小屋、小房間、替身工作、最終選擇。過一章蓋一個章（短動畫），下一格露出剪影和一個問句（第 1.1 節「每章結束時的疑問」）。
- 字型、字級照 `css/tokens.css`。

驗收：`npm test`、截圖、`check-santa-playthrough.mjs` 桌機＋手機（它會檢查線索數）。
