必須保留的行為：

- 初始顯示 `intro.PNG` 遊戲說明；按 Start 從第一關開始，立即啟動該關倒數。
- 每一關以 1 到該關配對組數的圖片編號各產生兩張，再以 Fisher–Yates 方式洗牌。
- 盒蓋作為卡背，盒子底座與禮物圖作為卡面；保留原本翻轉結構。
- **翻牌次數每翻開兩張才加 1**，每關重新歸零。不得沿用網站舊原型「每翻一張加 1」的定義。
- 成功配對後維持翻開；相同卡、已翻開卡、已配對卡及鎖定期間不能再次選取。
- 錯配等待 700ms 後蓋回，等待期間鎖定其他卡片。
- 當關完成後停止倒數，等待 500ms 顯示下一關橫幅；按確認才進下一關。
- 第五關完成顯示通關橫幅；確認後回第一關。
- 時間到顯示逾時橫幅；其中的重來按鈕重玩**當前關卡**。
- 遊戲下方的 Restart 按鈕會回到**第一關**，與逾時重玩不同。
- 不自行加入總分、跨關累計翻牌次數、離開畫面自動暫停或新的倒數規則。

## 4. 整合方式評估

| 方案 | 優點 | 需要處理的限制 | 結論 |
| --- | --- | --- | --- |
| 專案內保存原作，直接整合 HTML / CSS / JS | 可在 Game 原位遊玩；同一頁的焦點、響應式布局及完成特效較容易管理 | 要把全域 CSS 改為元件範圍，JS 改為獨立模組，並修正資源路徑及遮罩範圍 | **首選** |
| 本機同源副本 + iframe | 原始 CSS 與主站自然分離，原始頁面改動最少 | 框架高度、雙重捲動、iframe 內的滿版遮罩、鍵盤焦點、完成事件及 reduced-motion 都要另外協調 | 可作保留完整獨立頁面的備選 |
| 遠端 GitHub Pages + iframe | 快速展示原站 | 依賴遠端可用性與更新；跨來源不能直接讀取內部高度與 DOM；原作沒有高度／完成訊息橋接；也未完成專案內獨立副本的要求 | 不作正式整合方案 |

直接整合的工作量主要是封裝，不需要改寫另一款配對遊戲。會保留原來函式流程及 `levelConfig`，只調整與主站共存所需的邊界。

若改用本機 iframe：

- 來源會是專案內 `vendor/game2/index.html`，不指向遠端網址；使用者仍留在 Game 頁。
- iframe 提供明確 `title`、100% 寬度及內容高度同步；不能只設定固定高度並用 `overflow: hidden` 隱藏溢出。
- 原作 `body` 的 `min-height: 100vh`、垂直置中，以及彈窗的 `100vw / 100vh` 以 iframe 視窗計算，必須在副本外加嵌入專用樣式與測試，避免自動量高互相影響。
- 同源時可以在載入後觀察內容尺寸；用 ResizeObserver 時要避免高度更新循環，並在圖片解碼、關卡／彈窗切換及視窗改變後確認尺寸。
- 遠端跨來源 iframe 需由子頁主動用 postMessage 回報高度及完成事件，父頁不能自行取得；原作目前沒有這項介面。
- 使用 postMessage 時驗證 `origin`、`source`、訊息類型，傳送端指定實際 `targetOrigin`。
- 主站 CSS 和 reduced-motion 規則不會自動進入 iframe；需在子文件補上。鍵盤焦點也需跨文件檢查。

技術參考：[MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)、[ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)、[postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)。

- 保留 Game 頁「雪橇在上、配對在下」的 Wireframe 順序；下半部配對區改為原作的關卡列、花圈計時、說明／卡牌區、手繪按鈕與結果橫幅。

- 原作有全域 `*` 重設及 `body` 的 flex / min-height，不能整份直接套到主站；把必要的字體、背景與局部重設移至 `.hm-matching`。

- 原作的 `<main class="card-area">` 改為保留該 class 的普通容器，避免在主站 `<main>` 內嵌另一個 `<main>`，也避免主站 `main` 的 padding 影響遊戲。
- 原作遮罩是 `position: fixed; 100vw; 100vh; z-index: 1000`；適配為配對根容器內的遮罩及捲動範圍，不覆蓋主站導覽、音樂按鈕或雪橇遊戲。
- 保留遊戲原本約 650px 最大寬度、置中方式、奶白背景、字體及全部手繪美術；不改成網站原型的紅色文字卡片。

### JavaScript 與路徑

- 從原作 `script.js` 建立 `initChristmasMatchingGame(root)`，狀態與原有函式保留在此初始化範圍內。
- `document.getElementById(...)` 改成根容器內的查找，保留原來控制流程與 ID 語意。移除舊原型的活動標記後再接新標記，避免 `match-count`、`flip-count` 重複。
- `js/game.js` 改為分別初始化 `sleigh.js` 及 `game2-matching.js`；每款遊戲獨立管理計時、鎖定與事件。
- 圖片位置集中設定為 `vendor/game2/images/`。JS 動態圖片用相對 `import.meta.url` 的 URL；CSS 的盒子／盒蓋路徑以 CSS 檔實際位置重新計算。保留所有原始檔名，不依賴 GitHub 外連。
- 暫停主站舊配對模組的載入，但保留其檔案供歷史比對；不要同時啟動兩套配對邏輯。

### 保留規則下的必要修正

原作的 Restart 只清除 interval，未保存／取消錯配 700ms 及過關 500ms 的 timeout。若等待期間重開，舊 callback 可能清掉新回合的翻牌狀態或顯示錯誤橫幅。

適配時只補上 timeout 追蹤、重開／銷毀清理及回合識別檢查，保留 700ms / 500ms 時序。初始化回傳 `destroy()` 供頁面離開或未來重新掛載使用；重玩時也避免重複綁定確認按鈕事件。這些是生命週期修正，不改關卡難度或配對規則。

原作動態卡片是只有 click 事件的 div。適配可補上鍵盤操作、可辨識的狀態標籤、結果提示與彈窗焦點管理；使用 button 時將原生樣式局部重設，保留原本美術。結果橫幅需有明確文字替代，遊戲說明保留原圖並提供相同規則的可讀文字。

## 6. 響應式、動畫與效能

- 根容器 `width: 100%; max-width: 650px; min-width: 0`，由 Game 區域寬度決定尺寸。
- 沿用各關欄數及 `minmax(0, …)`，必要時讓資訊列換行；不把整個遊戲等比縮小而造成所有文字和按鈕過小。
- 圖片以 `contain` / 等比例高度呈現；按鈕、花圈及橫幅不得裁切。說明圖依原圖比例自適應，不強制裁成正方形。
- 特別檢查第五關六欄、320px 寬度、200% 文字縮放、橫向螢幕及彈窗完整可見性。若極窄畫面需要額外垂直空間，讓頁面自然增高，不以固定高度隱藏內容。
- 原來翻牌 0.5 秒與彈窗 popIn 保留，另補 reduced-motion 規則：減少動態時立即切換卡面及結果，不取消配對狀態或更改倒數秒數。
- 預留 `matching:level-start`、`matching:pair-match`、`matching:level-complete`、`matching:timeout`、`matching:complete` 事件；第五關完成才發出整體 complete。
- 未來 UI 特效監聽事件，不把彩帶／慶祝邏輯寫進配對判定；單一粒子層、`pointer-events: none`，並可依 reduced-motion 關閉。
- 首版保留原圖，實測圖片解碼與載入是否影響開局操作。若需要優化，可在說明畫面預載首關必要圖片；不擅自改用其他美術或有損縮圖。
